# MikroTik AmneziaWG Manager

Web-интерфейс для управления туннелями [AmneziaWG](https://amnezia.org/) на роутерах MikroTik с RouterOS 7.x, работающий через SSH.

# DISCLAIMER

Сделал для себя в первую очередь, и для тех кто хочет без лишнего геморроя обновлять конфиги AWG, управлять маршрутами и списками адресов/доменов идущих в впн или нет.

## Предыстория

AmneziaWG-туннели в последнее время нередко перестают работать — серверы блокируются, конфиги перестают работать и засирают логи wg-handshak'ами, и нужно регулярно их обновлять. Из-за особенностей установки (WireGuard-интерфейс + контейнер с прокси-агентом + маршруты + мониторинг) пересоздание одного туннеля приходилось делать вручную. Этот проект автоматизирует весь цикл: от генерации `.rsc`-скрипта до деплоя и мониторинга.

> **Примечание:** Конструктор Docker-контейнера для AmneziaWG (`awg-*` скрипты установки) изначально взят из репозитория **[timbrs](https://github.com/timbrs)** и переработан под личные предпочтения и конфигурацию сети. Обязательно дайте ему пожалуйста звездочку, потому что если бы не его конструктор, врятли было бы так просто кому угодно использовать AmneziaWG на своем Mikrotik.

## Принцип работы

Все операции с роутером выполняются **исключительно через SSH** (`paramiko`). API-порт MikroTik (`8728`/`8729`) намеренно не используется — ни снаружи, ни внутри сети. Это упрощает настройку безопасности: достаточно открыть только SSH и ограничить его по IP. В целом это можно было сделать и по API, но честно не хотелось.

```
Браузер → Flask (Docker) → SSH → MikroTik RouterOS
```

Каждый запрос к роутеру открывает SSH-сессию, выполняет RouterOS-команды и закрывает соединение. Никаких persistent-подключений, никакого хранения данных — всё читается с роутера в реальном времени.

## Возможности

### Деплой туннеля
- Загрузка `.conf`-файла AmneziaWG
- Автоматическая генерация `.rsc`-скрипта установки (`%%PLACEHOLDER%%`-шаблон)
- Автовыбор свободного WireGuard-порта (диапазон 12430–12466)
- Автовыбор свободного адреса veth-интерфейса (172.20–36.0.1)
- Деплой через SSH: удаление старого туннеля → SFTP-загрузка → `/import` → настройка мониторинга

### Мониторинг (Netwatch)
- Список всех netwatch-записей с текущим статусом (up/down/disabled)
- Редактирование параметров: тип (icmp/dns/simple), интервал, timeout, packet-count, thr-avg, dns-server
- Отображение текущего RTT Avg в реальном времени

### Маршруты
- Таблицы маршрутов (все `vpn*`), сгруппированные по routing-table
- Перетаскивание (drag-and-drop) для изменения дистанции
- Добавление и удаление маршрутов
- **Оптимизатор**: пинг всех шлюзов с самого MikroTik (5 пакетов), предложение оптимального порядка дистанций по RTT

### Address Lists & DNS Static
- Управление записями в листах `vpn`, `vpn-*`, `hike`, `unvpn`
- Только статические (не динамические) записи
- Сортировка: от новых к старым
- Группировка по листам, сворачивание групп
- Поиск/фильтр по адресу, домену, комментарию
- При добавлении автоматически подставляется `forward-to` IP, используемый в данном листе
- Массовое добавление: несколько адресов за один раз
- При удалении из address-list автоматически удаляется соответствующая DNS Static FWD запись

### Удаление туннелей
- Список всех `awg-*` скриптов удаления на роутере
- Запуск скрипта удаления (контейнер + WireGuard-интерфейс + маршруты + мониторинг)

## Установка

### Docker (рекомендуется)

```bash
git clone https://github.com/zack-37/mikrotik-manager
cd mikrotik-manager
```

Отредактируйте `docker-compose.yml.example` — уберите расширение ".example", и смените `SECRET_KEY`:

```yaml
services:
  awg-web:
    build: .
    container_name: mikrotik-awg-manager
    ports:
      - "5000:5000"
    restart: unless-stopped
    environment:
      - SECRET_KEY=your-secret-key-here
```

```bash
docker compose up -d
```

Интерфейс будет доступен на `http://docker-host:5000`.

### Локально (без Docker)

```bash
pip install -r requirements-web.txt
python web/app.py
```

Интерфейс будет доступен на `http://localhost:5000`.

## Использование

### Вход

При открытии приложения отображается форма входа. Введите SSH-реквизиты вашего MikroTik:

| Поле | Описание |
|------|----------|
| Host | IP-адрес роутера |
| Port | SSH-порт (по умолчанию 22) |
| User | Пользователь RouterOS |
| Password | Пароль |

Учётные данные хранятся **только в серверной сессии** (Flask session) и нигде не сохраняются на диск.

### Права пользователя RouterOS

Пользователю нужны следующие политики:

```
/user/group/set <group> policy=ssh,read,write,policy,ftp
```

### Деплой нового туннеля

1. Перейдите на вкладку **Деплой**
2. Загрузите `.conf`-файл AmneziaWG (полученный от провайдера/сервера)
3. Укажите тег — префикс для всех создаваемых объектов (например `awg-nl-prem`)
4. Нажмите **Деплой** — в окне вывода отобразится лог выполнения

Скрипт автоматически:
- Найдёт и удалит старый туннель с тем же тегом (если есть)
- Выберет свободный WireGuard-порт
- Выберет свободный адрес veth-интерфейса
- Загрузит `.rsc` на роутер и импортирует его
- Настроит или включит существующий мониторинг (netwatch + контрольный маршрут)

## Требования к MikroTik

- RouterOS 7.x
- Установлен пакет `container` (`/system/package`)
- Включён device mode с поддержкой контейнеров:
  ```
  /system/device-mode/update container=yes
  ```
- SSH включён и доступен с хоста, где запущен менеджер
- Достаточно места на диске (disk1) для образа контейнера

## API

Все эндпоинты требуют активной сессии (SSH-вход). Данные читаются с роутера при каждом запросе.

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/netwatch` | Список netwatch-записей |
| POST | `/api/netwatch/update` | Обновить параметры записи |
| GET | `/api/routes` | Маршруты из таблиц `vpn*` |
| GET | `/api/route/candidates` | Доступные wg-* интерфейсы для таблицы |
| POST | `/api/route/add` | Добавить маршрут |
| POST | `/api/route/delete` | Удалить маршрут |
| POST | `/api/route/set-distances` | Применить новые дистанции |
| GET | `/api/optimize/ping` | Пинг шлюзов с MikroTik |
| GET | `/api/addrlist` | Address list записи + fwd_by_list |
| POST | `/api/addrlist/add` | Добавить адреса в лист + DNS FWD |
| POST | `/api/addrlist/delete` | Удалить адрес из листа + DNS FWD |
| GET | `/api/scripts` | Список `awg-*` скриптов удаления |
| POST | `/api/scripts/run` | Запустить скрипт удаления |
| POST | `/deploy` | Загрузить `.conf` и задеплоить туннель |

## Безопасность

- Веб-интерфейс не имеет встроенной авторизации по пользователям — предполагается развёртывание во внутренней сети
- SSH-пароль не логируется и не сохраняется — живёт только в серверной сессии Flask
- `SECRET_KEY` для Flask сессий обязательно нужно установить в `docker-compose.yml`
- НЕ рекомендуется открывать порт во внешний доступ (firewall / reverse proxy с auth). Тем более учитывая что есть Back to Home.
- Если кому-то ну очень хочется можно прикрутить это всё к NGINX, и тд. Но мне лень.
